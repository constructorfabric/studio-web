По дороге — четыре находки, ни одна не в gear'е, кроме G-17:

**S-12 (studio) — схемы рёбер studio-connector несовместимы с gear'ом.** Типы рёбер
объявляли `x-gts-traits: {"full_text_search": []}`, а gear теперь сверяет трейты
типа с тем, что объявляет база, и база рёбер `full_text_search` не знает: вся
регистрация отклонялась. Компилятор этого не видит — «переход source-compatible»
из шага 2 верен для кода, но не для схем. Проверка всех наборов типов studio
через `POST /types/compatibility`: artifact-ingest (18), components-catalog (9),
domain-model (151) — ok, connector (8) — нарушение. Исправлено в
`connectors/gts.rs` (у рёбер нет трейтов), `docs/gts-types.json` перегенерирован.

**G-17 (gear) — апгрейд ломает уже зарегистрированные типы.** Анализ схемы идёт
**до** проверки побайтовой идентичности, в сервисе и в обоих хранилищах. На
развёртывании, где старая сборка уже сохранила эти рёбра с `full_text_search`
(studio-dev), после апгрейда: неизменённая схема → отказ анализа; исправленная →
`409 already registered with a different schema`, а `on_existing: update`
внутрипроцессный клиент передать не может. Итог: синхронизация на studio-dev
падает при любом варианте. Исправление — в #4794 (6.3), здесь воспроизведено не
было: на томе стенда этих типов не было.

**S-13 (studio-tasks) — вечная блокировка партиции.** Задача, от которой dispatch
отказался («gave up after 5 deliveries»), оставалась в голове партиции outbox:
обработчик на ней возвращал `Retry`, `processed_seq` стоял на месте, и все
следующие `graph_sync` той же партиции ждали бесконечно (задачи 10+ минут в
`queued`). Возникло после рестартов backend посреди работы. На стенде курсор
партиции сдвинут вручную (`studio_tasks_outbox_processor.processed_seq 1 → 4`).
→ studio: отказ от задачи должен подтверждать сообщение, а не ретраить.

**S-14 (toolkit-db, платформа) — outbox 0.16 не мигрирует существующие таблицы.**
В 0.16 у outbox появились колонка `body.trace` и таблица `*_outbox_trace`, но
**выпущенная миграция отредактирована под тем же именем** вместо новой. На базе,
созданной раньше, она считается применённой: у `studio_tasks` (и `studio_mini_chat`)
нет колонки `trace`, и **каждый enqueue падает** (`column "trace" … does not
exist`). types-registry сменил префикс и создал себе новый комплект таблиц; старые
остались сиротами с недоставленными сообщениями. На стенде: `ALTER TABLE … ADD
COLUMN trace` + удаление записи миграции из журнала (перезапуск идемпотентен). →
issue в gears-rust; **studio-dev упадёт на первом же enqueue после обновления**.

**S-15 (studio) — теряется причина отказа gear'а.** studio логирует
`invalid_argument: Request validation failed` без `field_violations`; причину
пришлось восстанавливать повторением запроса через REST.

## 6.3. Что блокирует

PG-линия тестов gear'а (testcontainers) не стартует: Docker Desktop перестал
выделять эфемерные порты хоста (`-P`, `0:5432` → `"5432/tcp": []`; явный порт
работает). Нужен перезапуск Docker Desktop — он остановит и посторонние
контейнеры машины, поэтому не сделан без пользователя.
